# YingYang v1.1.1

`develop/v1.2`에는 별도 [Staging A단계](docs/staging-a.md)가 추가되어 있습니다. 테스트 주소는 https://yingyangtest.web.app 이며 가상 테스트 계정으로만 서버에 접근합니다. 운영 앱은 v1.1.1을 유지합니다. 이 브랜치에서는 `npm.cmd run deploy:staging`만 사용하고 운영에 배포하지 않습니다. 전용 진입점·Functions·접근 방법·비용·검증 한계는 위 문서를 확인하세요.

나의 체질을 알아보는 두 가지 진단. React + TypeScript + Vite + Tailwind CSS로 만든 모바일 우선 정적 웹앱입니다. 백엔드와 데이터베이스 없이 브라우저에서 작동합니다.

## 실행

Node.js 22.12 이상과 npm이 필요합니다.

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. Windows PowerShell에서 npm 스크립트 실행이 차단되면 `npm.cmd ci`, `npm.cmd run dev`를 사용합니다.

```sh
npm test
npm run build
```

빌드 결과는 `dist/`에 생성됩니다. Firebase Hosting 프로젝트 `yingyangcheck`에 Firebase CLI로 수동 배포합니다. 자동 배포는 보류했으며 서비스 계정과 GitHub Secret 설정은 필요하지 않습니다. 사용자 로그인과 배포 절차는 [Firebase 배포 안내](docs/firebase-deployment.md)를 확인하세요. 상대 경로 자산을 사용하며 화면 전환은 앱 내부 상태로 처리하므로 서버의 URL rewrite 설정이 필요 없습니다.

## 구현

- 후천적 10문항·4지선다, 타고난 40문항·0~2점 선택
- 한 화면 한 문항, 미응답 시 다음 차단, 이전 답변 유지 및 수정
- 응답 진행률, 검진별 독립 시작·이어하기·결과 보기
- 검진별 localStorage 자동 저장과 새로고침 복구
- 응답 번호별 빈도 / 가·나·다·라 점수 집계 및 개별·종합 결과 표
- 완료 후 이전 응답 읽기 전용 확인
- 결과 화면에서만 재검진 제공, 확인·취소, 해당 검진만 초기화
- 모바일 반응형, 키보드 조작, 라디오 입력, 선택 체크 표시
- 저장 실패 안내와 잘못된 저장 데이터 검증
- 헤더에서 글자 크기 소·중·대 즉시 변경, 기본 중, 설정 저장·복구
- 검진 진행 화면에서 다른 완료 검진의 결과표 접기·펼치기

## v1.1 사용 편의 개선

글자 크기는 소(기존 수준), 중(소의 1.5배, 기본값), 대(중의 1.25배)로 제공하며 문항·선택지·설명·표·버튼에 함께 적용합니다. CSS의 `--text-scale`과 `rem`을 사용하므로 브라우저 글자 확대 설정도 반영합니다. 크기는 별도 키 `yingyang:text-size`에 저장하고 검진 응답은 변경하지 않습니다.

한 검진을 완료한 뒤 다른 검진을 진행할 때 상단의 ‘후천적 체질 결과 보기’ 또는 ‘타고난 체질 결과 보기’를 펼치면 기존 집계 함수로 계산한 완료 결과표가 표시됩니다. 기본은 접힘이며 현재 문항과 답변을 유지합니다. 미완료 검진의 중간 점수는 표시하지 않습니다. 두 검진을 모두 완료하면 기존 종합 결과 화면을 사용합니다.

변경 이력은 [CHANGELOG.md](CHANGELOG.md), 보존된 소스는 Git 태그 `v1.0.0`, `v1.1.0`으로 구분합니다. `v1.0.0`은 v1.1 변경 전 마지막 커밋 `c24a142`입니다. 기존 태그를 삭제하거나 덮어쓰지 않습니다. 소스 확인은 `git show v1.0.0:src/App.tsx`로 할 수 있고 별도 복원 폴더가 필요하면 `git worktree add --detach ../YingYang-v1.0.0 v1.0.0`을 사용합니다. 과거 태그를 확인하는 것만으로 실제 배포가 변경되지는 않습니다.

체질 판정이나 번호·분류와 체질의 대응 관계는 구현하지 않았습니다. 종합 결과도 두 검진의 점수를 서로 합산하지 않습니다.

## 코드와 데이터

- `src/questions.ts`: 사진에서 옮긴 문항, 강조 구절, 분류표
- `src/engine.ts`: 상태 전이, 검증, 저장·복구, 순수 집계 함수
- `src/App.tsx`: 홈, 공통 검진, 결과와 재검진 UI
- `src/preferences.ts`: 검진 데이터와 독립적인 글자 크기 설정
- `src/typography.css`: 글자 크기 배율과 접근성·반응형 보완
- `src/engine.test.ts`, `src/App.test.tsx`: 집계·복구·UI 시나리오 테스트
- `docs/source-review.md`: 원본 대조와 확인 필요 표현

저장 키는 `yingyang:acquired`, `yingyang:innate`입니다. 종류, 데이터 버전, 현재 문항의 0부터 시작하는 인덱스, 응답 배열, 완료 여부를 저장합니다. `null`은 미응답이고 `0`은 정상 응답입니다. 결과는 응답에서 매번 계산합니다. 데이터 버전이 다르면 해당 검진을 초기 상태로 복구하며, 문항 순서·내용 변경 시 `VERSION`을 올려야 합니다. 불완전한 데이터는 완료 상태로 취급하지 않습니다.

추후 체질 판정 함수는 집계 함수와 별도 모듈로 추가할 수 있습니다. 현재 판정 공식을 추정한 함수는 없습니다.

## 확인 범위와 제한

자동 테스트 33개는 기존 검진 기능과 글자 설정 전환·복구·오류 처리, 기존 데이터 보존, 완료 결과 접기·펼치기, 재검진 후 표시 갱신을 확인합니다. Chrome에서 320·390·768·1440px, 세 가지 글자 크기와 200% 글자 확대를 검증하고 대표 스크린샷을 검수했습니다. 실제 모바일 기기와 Safari 등 다른 브라우저 검증은 별도로 필요합니다. 자세한 결과는 [검증 기록](docs/verification.md)에 있습니다.

응답은 같은 브라우저·같은 사이트 주소에서만 복구됩니다. 다른 기기와 동기화하지 않으며, 브라우저 데이터 삭제 시 사라집니다. 동시에 여러 탭에서 답변하면 마지막 저장이 적용됩니다. 저장 공간이 차단되면 현재 열린 페이지 내 응답은 유지되지만 새로고침 복구는 보장하지 않습니다.

원본 문항과 강조 표시를 옮겼으며 어색한 표현은 수정하지 않았습니다. 자세한 대조 사항은 [원본 대조 기록](docs/source-review.md)을 확인하세요. 설치 도중 npm의 선택적 peer 의존성 해석 오류를 피하기 위해 `.npmrc`에 `legacy-peer-deps=true`를 설정했고 테스트용 DOM 의존성은 명시적으로 선언했습니다.
