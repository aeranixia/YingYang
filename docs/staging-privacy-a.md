# A안 개인정보 보호 기능 — Staging 검수 기록

2026-10-31. 이슈 #4 댓글6422925559 및 사용자 ‘진행해’ 승인 범위. 대상 develop/v1.2 / yingyangtest. 실제 개인정보처리방침·법률 관계의 확정이나 운영 배포 승인이 아니다.

## 구현 화면과 데이터 흐름

- 로그인 및 Auth/App Check 환경 확인 뒤 **검사 시작 전 고지/일반 개인정보와 건강 관련 민감정보 분리 동의**를 표시한다. 체크 기본값은 미선택. 둘 다 동의하지 않으면 검진 화면·이어하기·완료 확인·전송 화면을 열지 않는다.
- 최초 동의 요청은 버전/각 동의만 보내며 검사 응답·이름·전화번호를 보내지 않는다. 서버가 기존 서명 키로 계정/버전/서버 동의 시각/7일 만료에 결합한 증명을 발급한다. 재접속 시 응답 없이 증명을 서버 검증한 뒤 자료를 복원한다.
- 기존 stagingStatus 함수에 동의/검증 동작을 추가했다. 완료 확인과 모의/실메일 제출 endpoint에서 유효한 동의 증명을 요구한다. 새 함수·DB·유료 서비스 없음.
- 실제 건강 응답은 사전 동의 후 마지막 검진 완료 확인 요청에서 전송한다. 검사 완료 확인 시각은 여전히 별도 서버 사건이며 동의 시각을 대신하지 않는다.
- 문구는 ‘Staging·가상 자료·검토용’으로 표시한다. 운영 주체, 제공/위탁 관계, 국외 이전 근거, 문의처, 법적 보관·장기 동의 증빙이 미확정임을 화면에 명시했다. 일반 사용자 화면은 계속 모의 전송이다.

## 저장·만료·기존 데이터

기존 응답 키/문항/집계와 v1 구조를 유지하고 Staging 저장 어댑터를 추가했다. 별도 보관 메타데이터에는 검사별 마지막 실제 저장 시각을 기록한다. 글자 변경/단순 조회/복원은 보관기간을 연장하지 않는다.

검사별 저장 후7×24시간 경계에 만료하며, 해당 검사와 통합 완료 증명을 제거하고 다른 유효 검사는 유지한다. 만료/동의/회차/원 응답을 시작·복원·저장·완료 확인·제출·탭 재활성화·storage 이벤트에서 검사한다. 열린 화면은1초 주기로 만료를 점검한다. 닫힌 브라우저에서는 물리 삭제를 실행할 수 없으므로 다음 실행 시 제거한다.

완료 증명의 만료는 양쪽 검사 만료 및 동의 증명 만료 중 빠른 시각을 넘지 않는다. 서버도 서명된 완료 증명 만료를 검사한다. 동의 증명은 서버 발급 후7일이며, 그 전에 저장된 응답의 로컬 만료를 자동 연장하지 않는다. 동의가 먼저 만료되면 새로 동의를 받고 아직 유효한 검사만 이어갈 수 있다.

기존 응답은 자동 이전/임의 삭제하지 않는다. ‘이전해 이어하기’ 또는 ‘삭제하고 새로 시작’을 명시적으로 선택한다. 실제 저장일을 알 수 없는 자료는 이전 승인 시점부터7일임을 안내한다. 기존 완료 확인 증명은 정책/만료를 검증할 수 없어 선택 이전 시 무효화하며 과거 완료 시각을 새로 만들어 채우지 않는다. PDF의 기존 ‘기록 없음’ 처리를 유지한다.

로컬 저장 시각은 이용자가 조작할 수 있다. 따라서 로컬7일 정책은 기기 자체의 악의적 변조/백업 복구 방지 장치가 아니며 서버 동의·완료 증명의 서명/계정/만료 검증과 구별한다. 서버에 회차 취소 DB를 만들지 않았으므로 악의적으로 복사해 둔 유효한 증명의 원격 취소를 보장하지 않는다.

## 전체 삭제와 경쟁 상태

‘검사 데이터 모두 삭제’ 확인창에서 두 검사 응답/진행, 완료 증명, 관련 임시 동의/보관 메타데이터 및 현재 폼을 초기화한다. 글자 크기와 무관한 키는 보존한다. 재검진은 해당 검사만 초기화하고 통합 증명을 무효화한다.

교차 탭/비동기 요청을 위한 무작위 회차 표식만 남기며 응답이나 동의 내용은 담지 않는다. 삭제·만료 시 이전 저장 어댑터와 지연 응답의 회차/스냅샷 검증이 실패하므로 데이터를 다시 쓰지 못한다. 다른 탭 변경은 검사 화면을 재마운트하여 입력 중인 오래된 메모리/폼을 제거한다. 검진 저장과 메타데이터 저장 중 오류가 생기면 기존 응답을 복구하고 전송을 차단한다.

이미 서버에 접수된 요청이나 이메일·로그·백업은 브라우저 삭제로 취소/삭제되지 않는다. 화면에 이 한계와 공유기기/로그아웃 차이를 표시한다. 전송 성공/불명 후 임의 자동 실메일 재발송 경로를 추가하지 않았다.

## 사용자 검수 방법

1. Staging에 기존 테스트 계정으로 로그인하고 환경 확인. 사전 고지 화면에서 한 항목만 동의할 때 검사 시작이 비활성인지 확인.
2. 기존 자료가 있다면 선택 전 응답이 표시되지 않는지, 이전 기준이 지금부터7일임을 안내하는지 확인. 허용된 가상 응답만 이전/사용.
3. 동의 후 검사 시작·이어하기·이전 문항·독립 재검진·글자 크기·완료 확인·모의 전송 확인. 재접속에는 재로그인 및 유효한 동의 증명 검증이 필요.
4. 다른 탭도 열어 같은 브라우저의 검사 자료를 확인. 한쪽에서 전체 삭제 후 다른 탭에도 검사 화면/입력이 남지 않는지 확인. 글자 크기는 유지.
5. ‘삭제하고 새로 시작’ 선택 시 기존 응답을 지운 뒤 다시 동의를 요구하는지 확인. 삭제는 이미 보낸 메일을 취소하지 않음.

실메일 전송 버튼은 제공하지 않는다. 실제7일 경과/실기기·Safari·기기 백업 완전 파기 검증을 이번 자동 시험으로 대체하지 않는다.

## 남은 승인/운영 사항

운영 주체·한의원 업무 수신 동의·제공/위탁·국외 이전·담당 문의처·법정 보관 및 동의 장기 증빙은 미확정이다. 서버 동의 서명은 현재 Staging 동작 검증용이며 서명 증명만으로 법적 동의 입증이 완결된다고 주장하지 않는다. 메일/다운로드 사본 삭제 책임과 OAuth 장기 운영·실제 기기 검증, 운영 화면/배포는 별도 검토·승인 대상이다. 이슈 #4를 열린 상태로 유지한다.
