## PDF

기존 서버 PDF 테스트를 재실행하고 로컬에서 가상 PDF를 렌더링해 한글·원형 숫자·표·합계 배치를 확인했다. A4 595.28×841.89pt / 1페이지, 이름·전화번호, 한국 날짜 및 서버 접수일 정의, 두 독립 집계표, `이름_전화번호끝4자리.pdf` 생성이 통과했다. UTC `2026-10-26T15:30:00Z`를 주었을 때 한국 날짜 `2026-10-27`을 확인했다. 실제 날짜를 잘못 표시한 것이 아니라 자정 경계의 가상 시각 시험이다. 폰트와 라이선스는 서버 번들에 고정되어 있고 실행 중 외부 다운로드가 없다.

서버는 PDF를 메모리에서 만들고 모의 발신 후 Buffer를 정리하며 브라우저에 PDF/점수/인적사항을 반환하지 않는다. 개발 검수용 가상 PDF/PNG만 로컬 임시 폴더에 만들었고 저장소에 결과 PDF를 추가하지 않았다.

## 장애·중복·재시도

- 모의 실패 후 동일 ID로 성공, 완료 요청 재호출 시 모의 발신 생략, 다른 입력에 같은 ID 거부, 3회 시도·10분 논리 TTL·하루 로컬 50회 제한: 기존 테스트 재사용.
- 새로운 로컬 동시 요청 10개: 처리 중 같은 ID는 9개 거부하고 모의 발신 1회만 수행.
- PDF 생성 예외는 원문 오류를 전달하지 않고 재시도 가능한 알려진 모의 실패로 처리.
- 별도 **로컬 Node 프로세스**에서 완료 표식을 확인한 뒤 종료/재시작하면 같은 ID도 새 요청으로 처리되는 한계를 확인. PDF 단계에서 대기 중인 프로세스도 종료/재시작 후 표식이 사라졌다.
- 실제 Staging에서 서버가 모의 성공한 응답을 브라우저에 전달하기 직전 차단했다. 화면은 실패를 안내했고 같은 ID 재시도는 서버가 중복 완료로 반환했다. 메모리 표식이 살아 있는 경우의 검증이다.
- 클라우드 함수 timeout=30초 설정은 조회했다. **실제 클라우드에서 의도적인 30초 초과 실행·프로세스 강제 종료·메모리 고갈·지속 고부하는 수행하지 않았다.** 로컬 종료 시험을 클라우드 장애 재현으로 보고하지 않는다. 응답 유실은 강제 서버 timeout과도 다르다.

메모리 상태는 재시작/새 리비전/복수 인스턴스를 넘지 못한다. 입력 폼을 벗어나면 요청 ID도 사라져 새 전송이 가능하다. 현 상태로 실제 Gmail의 전역 중복/한도/결과 불명을 안전하게 해결했다고 보지 않는다. 실제 발송 전 공유 상태 승인과 결과 불명 시 자동 재발송 중지 설계가 필요하다.

## 배포·리소스·비용

최초 수정 배포는 Firebase Hosting API 연결 타임아웃으로 중단됐고 같은 대상에 재시도해 성공했다. 최종 공개 HTML은 로컬 산출물과 일치한다. 각 함수 ACTIVE, 최소 0/최대 1, 동시성 1, 512MiB/CPU1/30초, 서울 리전, 모의 설정 유지. 한 함수의 최대 1이 전체 합계 상한이나 절대 비용 상한은 아니다.

이미지 1일 정리 정책이 실제 삭제 모드임을 확인했다. 월 KRW 10,000 예산, 50/90/100% 알림 기준은 유지됐다. 실제 누적 청구액/알림 수신은 확인하지 않았고 예산을 과금 차단 장치로 표현하지 않는다. 추가 상시 리소스/API/Secret/공유 저장소·결제 변경은 하지 않았다. 배포에 따른 코드/이미지 버전과 테스트용 임시 Auth 계정 생성/삭제만 발생했다.

현재 기본 실행 계정이 `roles/cloudbuild.builds.builder`를 공유한다. Secret 접근은 개별 서버 키로 제한했지만 실행 계정의 빌드/저장 권한은 필요 이상일 수 있다. 키 없는 실행 계정 분리와 최소 권한 변경은 실제 개인정보/Gmail 도입 전 승인해 해결해야 한다. D에서 임의 계정 생성/권한 변경은 하지 않았다.

운영 HTTP 200 및 D 시작 전후 HTML SHA-256 동일, main `cd0bf2d`, 기존 v1.0.0/v1.1.0/v1.1.1 태그 보존. 운영 v1.1.1 배포·설정·데이터를 변경하지 않았다. v1.2.0 출시 태그도 생성하지 않았다.

## 판단과 E단계

승인된 Staging 모의 기능에 대한 D검증과 발견 문제 수정은 완료했다. 실기기/Safari·클라우드 강제 장애·지속 부하·운영 개인정보 정책 및 위 잔여 위험은 미완료이며 운영 준비 완료를 의미하지 않는다.

[E단계 사전 검토](staging-e-preparation.md)에 **개인 Gmail 발신 → 개인 네이버 테스트 수신**, **한의원 운영 수신 주소/서비스 미정**을 반영했다. 환경별 고정 서버 수신자, OAuth 권한·검증/토큰 수명, 저비용 GCS 후보, 중복/횟수 제한·결과 불명, 메일 보관/삭제, 추가 비용과 사용자 승인 항목을 정리했다. OAuth·실제 발송·새 공유 저장소는 승인 전 실행하지 않는다.
