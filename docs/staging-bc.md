# v1.2 Staging B·C단계

2026-10-26, 이슈 [#4](https://github.com/aeranixia/YingYang/issues/4). B·C단계 승인 범위만 구현했다. D 이후, Gmail OAuth, 실제 이메일, 공유 저장소, 운영 배포는 별도 승인 대상이다. 운영은 v1.1.1, 개발 브랜치는 `develop/v1.2`이며 출시 태그는 추가하지 않는다.

## 접속과 직접 확인

주소는 https://yingyangtest.web.app 이다. [A단계 접근 안내](staging-a.md)의 가상 테스트 계정과 Secret Manager 비밀번호를 사용한다. 로그인 후 ‘테스트 접근 권한과 서버 확인’을 눌러 서버 권한 및 실제 App Check를 확인하면 검진 화면이 열린다.

로그인 비밀번호는 Secret Manager의 사용 설정된 최신 버전에서 **비밀 값 보기/복사**로 확인한다. 버전 번호·리소스 이름·인코딩된 API 응답을 비밀번호로 입력하지 않는다. 앞뒤 공백은 제거한다. 로그인 실패 시 화면의 안전한 오류 코드와 실패 단계만 공유하고 비밀번호/토큰은 공유하지 않는다. 네트워크 차단·일시적 요청 제한 등은 각각 별도로 안내한다.

1. 실제 건강정보 대신 임의의 가상 응답으로 후천적 10문항과 타고난 40문항을 완료한다.
2. 두 검진 완료 후 ‘결과 보내기 (모의)’에서 이름·전화번호·별도 동의를 입력한다. 마지막 검진 완료 시 이 화면으로 자동 이동한다.
3. 허용된 가상 이름은 `가상테스터` / `테스트환자`, 가상 전화번호는 `01000001234` / `01000005678`뿐이다. 전화번호 하이픈은 브라우저에서 제거한다. 서버에서도 이 목록 외 인적사항은 거부한다. 응답이 가상인지 자동 판별할 수 없으므로 실제 응답을 입력하지 않는다.
4. 개인정보 수집·이용과 건강 관련 민감정보 동의를 별도로 선택하고 가상 정보 확인도 선택한다. 문구에는 **임시 초안, 운영 사용 불가**를 표시했다. 미동의 시 모의 처리를 이용할 수 없다.
5. ‘정상 처리’는 PDF 생성 후 모의 성공을 반환한다. ‘처음 실패 후 재시도 성공’은 첫 모의 발신을 실패시키며, 동일 입력으로 재시도하면 성공한다. 수정된 입력은 새 요청 ID를 사용한다.

성공 화면도 **실제 이메일은 발송되지 않았음**을 명시한다. 실제 수신함, 상담 접수 또는 한의원 연락 기능은 없다. 미확정 한의원 연락처를 추정해서 넣지 않았다. PDF 다운로드나 점수표 직접 조회는 제공하지 않는다. 기존 검진별 응답 확인·재검진은 유지한다.

로그인은 메모리 세션이다. 새로고침 시 다시 로그인하지만 기존 검진 답변·진행 상태·글자 크기는 같은 테스트 사이트의 브라우저 저장소에서 복구한다. 이름·전화번호·동의·전송 요청은 localStorage/sessionStorage에 저장하지 않는다. 실패 시 열린 폼 메모리에만 입력을 유지하고 성공 시 지운다. 폼을 벗어나거나 새로고침하면 재입력해야 한다. 운영 주소의 브라우저 데이터를 가져오지 않는다.

## 서버와 PDF

`submitMockReport` callable은 Auth 가상 테스터 claim 및 App Check를 강제한다. `GCLOUD_PROJECT=yingyangtest`, `STAGING_ENV=stage-bc`, `MAIL_MODE=mock`, `SEND_ENABLED=false`를 모두 확인한다. 브라우저가 수신자·점수·추가 필드를 보내면 거부한다. 문항 버전 1, 10/40개 정수 응답, 각 범위(1~4 / 0~2), 지정 가상 이름/번호, 세 동의 및 초안 버전, UUID v4, 모의 시나리오를 검증하고 8KiB 초과 본문을 거부한다.

집계는 복사한 분류표 대신 **기존 `src/engine.ts`와 `src/questions.ts`를 서버에서도 직접 컴파일**해 재사용한다. 서버 실행 파일과 해당 공유 소스의 컴파일 결과는 Functions `lib/` 안에 함께 배포한다. 운영의 집계·문항·저장 키/데이터 버전은 변경하지 않았다. `App`은 선택적 Staging 제출 화면을 받으며 기본 운영 렌더링은 기존 동작을 유지한다.

PDFKit으로 A4 1페이지를 서버 메모리 Buffer에 생성한다. 이름·전체 전화번호·한국 시간 검사일, 후천적 ①②③④ 선택 횟수/합계, 타고난 가·나·다·라 총점/합계를 각각 표시한다. 두 검진은 합산하지 않고 체질 판정도 추가하지 않았다. 검사일은 실제 완료 시각을 추정하지 않고 **두 검진 완료 후 서버가 모의 요청을 접수한 한국 날짜**로 정의하고 PDF에 명시한다.

첨부 이름은 `이름_전화번호끝4자리.pdf`이며 모의 발신 인터페이스에 전달한다. 예: `가상테스터_1234.pdf`. 파일명 생성은 경로·제어 문자 등을 제외하고 길이를 제한한다. 브라우저에는 PDF·파일명·점수·인적사항을 반환하지 않고 모의 처리 상태, 요청 ID, 중복 여부만 반환한다.

`sender.ts` 인터페이스의 모의 구현은 첨부 형식을 확인하고 모의 성공/실패만 반환한다. SMTP/Gmail·외부 메일 요청·수신자 설정은 구현하지 않았다. 실제 메일용 Secret도 생성하지 않았다. PDF는 DB·Cloud Storage·서버 파일에 쓰지 않고 처리 후 참조를 해제한다. 사용한 Buffer는 finally에서 덮어쓰며, 런타임 내부의 모든 메모리 사본에 대한 즉시 물리 삭제를 보장한다는 뜻은 아니다. 앱은 요청 본문·PDF·원본 예외·인적사항을 로그로 출력하지 않는다. 플랫폼 로그의 종합 점검은 D단계 대상이다.

## 임시 상태와 제한

공유 저장소는 생성하지 않았다. 프로세스 메모리에 요청 ID·테스터 ID·서명된 입력 해시·상태·시도 횟수·만료 시각만 둔다. 이름·전화번호·응답·점수·PDF 원문은 처리 표식에 저장하지 않는다. 메타데이터를 완전한 익명정보로 단정하지 않는다.

- 같은 요청 처리 중: 중복 진입 거부. 성공한 같은 요청: 모의 발신 없이 동일 처리 완료 상태 반환.
- 같은 ID에 다른 입력: 거부. 알려진 모의 실패는 같은 ID로 최대 3회 시도.
- 논리 TTL 10분, 만료 항목은 다음 호출 시 제거. 프로세스 메모리 표식 최대 100개.
- 모의 처리 함수는 프로세스 단위 분당 5회 및 UTC 날짜 기준 50회 생성 시도 제한. 상태 확인 함수와 별도다.
- 재시작·새 리비전·다중 인스턴스를 넘는 전역 중복 방지/횟수 제한은 보장하지 않는다. 모의 성공의 응답 유실 후에도 메모리 표식이 살아 있으면 재시도 시 재생성하지 않는다.

실제 Gmail 전에 비공개 Cloud Storage 등 대안·만료/삭제 의미·추가 비용을 비교 보고하고 공유 상태 승인을 받아야 한다. 실제 메일에서 결과 불명/재시도 정책을 이 모의 구현만으로 해결했다고 보지 않는다.

## 리소스·비용

기존 테스트 프로젝트에 모의 callable 하나를 추가했다. `stagingStatus`, `submitMockReport` **각각** 최소 0 / 최대 1, 동시성 1, 서울 리전, 512MiB, CPU 1, timeout 30초다. 두 함수의 합계 상한이 1이라는 뜻은 아니다. 별도 상시 서버·서비스 계정·API·Secret·공유 저장소는 추가하지 않았다. A단계의 이미지 1일 정리와 월 1만원 알림은 유지한다. PDF 처리·추가 배포의 실행/빌드/저장 비용이 발생할 수 있으며 예산은 과금 차단이 아니다.

## 폰트와 라이선스

실행 중 외부 폰트를 다운로드하지 않는다. SIL OFL 폰트와 라이선스를 `functions/assets/`에 함께 보관한다. 폰트는 서버 배포에만 포함하고 Hosting에는 올리지 않는다.

| 폰트 | 출처 | SHA-256 |
| --- | --- | --- |
| NanumGothic-Regular.ttf | [Google Fonts](https://github.com/google/fonts/tree/main/ofl/nanumgothic) | `76f45ef4a6bcff344c837c95a7dcc26e017e38b5846d5ae0cdcb5b86be2e2d31` |
| NotoSansSymbols.ttf | [Google Fonts](https://github.com/google/fonts/tree/main/ofl/notosanssymbols) | `f7e7e04b4a24b6c78893d50cbfd2b2f6cae49617ab047bfef668d252adb128f7` |

나눔고딕에 원형 숫자가 없어 별도 Noto Symbols 글리프를 사용한다. PDF 텍스트 추출은 기호를 숫자로 정규화하지 않는 옵션으로 검증했다. PDF.js는 테스트 전용이며 보안 감사 결과를 반영해 `5.5.207`로 고정했다.

## 검증과 한계

- `npm test`: 기존 33개 유지 + 신규 UI 3개 = 36개, 배포 보호 2개(오설정 10종) 통과.
- Functions 테스트 10개: 검증·동의·수신자 변경/점수 주입 거부, 정확한 서버 집계, 안전한 파일명, 한글/기호/KST 날짜/A4/1페이지, 모의 첨부·Buffer 정리, 실패/재시도·중복·TTL·로컬 한도 통과.
- 운영 `npm run build`, Staging 및 Functions TypeScript 빌드 성공. 루트·서버 실행 의존성 audit 0개.
- 가상 PDF를 로컬 렌더링해 이름·번호·한글·원형 숫자·두 집계표·합계가 잘리지 않는 것을 시각 검수했다. 이 로컬 QA 산출물만 임시 폴더에 두었으며 서버 저장 기능은 없다.
- 실제 배포 주소 Chrome에서 50문항 완료, 무응답 이동 차단, 새로고침/재로그인 후 이어하기, 점수표 없음, 동의 전송 차단, 모의 실패→같은 ID 재시도 성공, 중복 요청 완료 반환, 수신자 주입 400 거부 확인.
- 모의 성공 후 이름·전화번호 비우기와 브라우저 인적사항 미저장, 검진 답변 보존, 검진별 독립 재검진 확인. 페이지 실행 오류 0개.
- 320/820/1440px × 소/중/대 9조합 가로 넘침 없음. 390px 폼 캡처 검수.
- 운영 HTTP 200 및 기존 HTML SHA-256 동일. 운영 배포/설정 변경, main 병합, 태그 추가·변경 없음.

이는 B·C 기능 검증이다. **D의 종합 회귀·보안·로그·부하·브라우저 검증 완료를 뜻하지 않는다.** 실제 모바일·태블릿 기기/Safari, 나머지 너비의 전체 조합, Gmail 실제 발송, 공유 상태 및 장애 시나리오, 법률 검토/실제 동의 문구는 미완료다. D 이후는 사용자 승인 전 진행하지 않는다.
