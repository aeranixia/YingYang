## 결론과 승인 전 차단 사항

현재 구현은 가상 자료 Staging 시험용이다. PDF 최종 승인은 개인정보 정책이나 운영 출시 승인을 대신하지 않는다. ‘앱이 PDF를 저장하지 않는다’와 ‘어디에도 개인정보가 남지 않는다’는 다르다.

1. **동의 시점:** 현재 마지막 검진 완료 시 `stagingStatus`로 50개 응답을 전송하며, 이름/전화번호 입력 및 동의 화면보다 앞선다. 브라우저 자동 저장도 검사 시작부터다. 운영은 검사 시작 전 처리 안내와 필요한 별도 동의를 받거나, 동의 전 서버 전송을 없애는 설계 승인이 필요하다. 후자의 경우 완료 확인 시각이 동의 후 시각으로 늦어질 수 있다.
2. **처리 책임:** 앱 운영 주체, 한의원 공식 명칭·책임자, 위탁/제3자 제공 관계, 개인정보 문의처와 실제 보유기간이 미확정이다. 주소를 확보했다고 계약·운영 동의가 확인된 것은 아니다.
3. **국외 처리:** 서울 Functions/GCS만으로 Firebase Auth/reCAPTCHA/개인 Gmail의 국내 처리·보관을 보장할 수 없다. 계약 상대방·처리 국가·하위 처리자·보유기간과 적법 근거를 확인해야 한다.
4. **사본 및 동의 증빙:** 보낸편지함·수신함·다운로드·캐시/백업에 사본이 남는다. 동의 체크/버전은 요청에만 있고, 장기적으로 확인 가능한 동의 이력은 현재 없다. 보유·파기 책임 및 최소 증빙 방식을 승인해야 한다.
5. **운영 기술:** 일반 사용자 화면은 여전히 모의 발송이며 실발송은 운영자 전용 별도 경로다. 실제 이름/번호는 서버에서 거부한다. 운영 기능·접근 제한·동의 UI의 변경은 별도 개발 승인 대상이다.

근거: [제15조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0015&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제17조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0017&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제23조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0023&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제26조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0026&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334957).

민감정보 동의가 제3자 제공/국외 이전 검토를 자동 대체하지 않는다. 반대로 클라우드 업체를 모두 한의원과 같은 제3자 수신자로 적는 것으로 위탁 관계를 해결할 수도 없다. 역할별 계약·고지와 필요한 동의를 정한 뒤 문구를 확정한다. [Firebase 공식 개인정보 안내](https://firebase.google.com/support/privacy)는 지역 선택이 없는 기능의 처리 위치가 단일 국가에 고정된다고 보장하지 않는다. 한국법상 역할은 해당 계약과 실제 운영을 별도로 검토한다.

## 동의 문구 초안 — 화면 미반영

다음 `[대괄호]`는 빈칸 그대로 운영에 게시할 수 없다. 아래 7일/30일은 제안값이지 법정 보유기간이 아니다. 최종 정책이 달라지면 전 문구를 함께 수정한다. 사전 선택/일괄 동의를 사용하지 않고 동의하지 않아도 되는 항목과 필요한 항목을 구분한다.

### A. 검사 시작 전 개인정보 수집·이용 안내/동의 초안

> 처리자: [법적 운영 주체명]. 문의 및 열람·정정·삭제·동의 철회: [담당자/공식 연락처]. 목적은 응답 임시저장·이어하기, 완료 확인, 결과 PDF 생성과 요청한 한의원 전송, 상담 접수 연락 및 전송 장애 처리입니다. 항목은 이름·전화번호·완료 확인 시각·동의 내역 및 전송 상태입니다. 건강 관련 문항 응답·집계는 아래 별도 동의 항목입니다. 브라우저 응답/확인 기록은 [최종 저장 후 7일 및 사용자 삭제 시], 서버의 요청 원문/PDF는 처리 중 메모리에서 사용하고 앱 저장소에 영구 보관하지 않습니다. 단, 보낸메일·한의원 수신메일·다운로드와 서비스 접속/감사기록은 각각 아래 정책에 따라 남습니다. 동의를 거부할 수 있으며, 거부하면 이 경로의 검사 저장·완료 확인·결과 전송을 이용할 수 없습니다. [대체 상담 경로]는 별도로 문의할 수 있습니다.

체크 예시: `개인정보 수집·이용에 동의합니다.` 실제 입력은 검사 후여도 미리 처리 범위를 안내한다. 서비스 사용에 필요하지 않은 마케팅 목적을 섞지 않는다. 상담 연락 목적은 한의원이 실제로 동의한 범위로 한정한다.

### B. 민감정보 처리 별도 동의 초안

> [처리자]는 건강/생활 특성과 관련된 후천적10문항·타고난40문항의 응답과 항목별 집계를 검사 저장·이어하기, 서버 완료 확인·재집계, PDF 생성 및 요청한 한의원 전송을 위해 처리합니다. 이 집계는 체질 판정이나 의료 진단을 제공하지 않습니다. 브라우저·메모리·메일/다운로드의 보유·삭제는 [확정 정책]을 따릅니다. 동의를 거부할 수 있으며 거부 시 해당 응답 처리와 PDF 전송을 이용할 수 없습니다. [대체 상담 경로] 이용 여부는 한의원에 문의할 수 있습니다.

체크 예시: `건강 관련 민감정보 처리에 별도로 동의합니다.` 동의는 첫 응답의 저장·전송 이전에 받아야 하는 방향으로 제안한다. 운영자·한의원의 역할에 따라 민감정보 제공 범위까지 분리·명시할 필요가 있는지 검토한다.

### C. 제3자 제공으로 확정되는 경우의 별도 초안

> 제공받는 자: [한의원 정식 명칭]. 목적: [검사 결과 확인과 요청된 상담 접수/연락]. 제공 항목: 이름, 전화번호, 서버 완료 확인 시각, 후천적/타고난 각 집계표가 들어 있는 PDF 및 식별 가능한 첨부파일명. 원 문항별 응답은 현재 PDF에 포함하지 않습니다. 받는 자의 보유기간: [접수 목적 종료 시 지체 없이 삭제, 늦어도 수신일부터 30일이라는 제안에 대한 한의원 확정값]. 진료기록으로 편입되는 자료는 [적용 근거·항목·기간]을 별도로 고지합니다. 제공 동의를 거부할 수 있고 거부하면 이 앱의 한의원 결과 전송은 이용할 수 없습니다. 다른 진료·상담 서비스 전체가 제한된다고 안내하지 않습니다.

체크 예시: `[한의원명]에 위 항목을 제공하는 데 동의합니다.` 위탁/동일 처리자로 결론나면 이 블록을 자동 채택하지 않고 위탁 공개·계약 및 내부 접근 고지로 재구성한다.

### D. 국외 이전이 별도 동의를 근거로 하는 경우의 미완성 초안

> 이전받는 자/연락처: [계약 검증 후 기재]. 국가: [제품별 확인]. 항목: [검진 데이터, 접속/보안 신호 등을 실제 전송별 구분]. 목적: [서버 처리/보안 검증/메일 전송·보관]. 시기·방법: [제품 초기화·완료 확인·전송 시 암호화 통신 등]. 보유기간: [제품·메일 사본별 확정]. 이전 거부 방법과 절차: [문의처/동의 거부/철회 방법]. 거부 시 효과: [해당 전송 방식 이용 불가 및 대안].

공식 국가/연락처/기간을 확인하기 전에는 추정 국가나 ‘글로벌’만으로 빈칸을 채우지 않는다. 별도 동의 이외의 근거 적용 여부도 법률 검토 후 결정한다.

### E. 전송 직전 요약과 동의 증빙 제안

전송 화면은 수신 한의원 정식 명칭, PDF 항목·식별 파일명, 메일함과 다운로드에 사본이 남는 점, API 접수와 실제 수신의 차이, 취소 불가/삭제 요청 연락처를 알린다. PDF 디자인 자체는 유지한다.

현재 체크값/문구 버전은 요청 검증과 HMAC의 재료일 뿐 장기 동의 증거가 아니다. **동의 시각과 검사 완료 확인 시각은 구분해야 한다.** 원 응답/개인정보 DB를 새로 만들지 않는 조건에서 최소 동의 증명(최종 문구 버전·각 동의·동의 시각·처리자/수신자·요청 식별 연결)을 한의원 관리 기록 등 어디에 얼마 동안 보관할지 별도로 설계·승인받는다. 브라우저 증명만으로 삭제 후에도 입증 가능하다고 주장하지 않는다. 보관 근거·범위 확정 전 새 저장소/추가 PDF·메일 첨부 기능을 만들지 않는다.

[Cloud Logging 보관 안내](https://docs.cloud.google.com/logging/docs/store-log-entries)도 서비스 로그와 앱 데이터 보관을 구분한다. 실제 공급자 백업 파기 기간은 계약/지원 확인 전 확정하지 않는다.

## 운영 전 우선순위 점검표

`P0`는 실환자 처리/운영 승인 전 해결, `P1`은 출시 검증 계획에 포함, `P2`는 출시 후 정기 운영 계획이다. 체크 해제는 미완료/승인 필요를 뜻한다.

| 우선 | 확인/제안 | 담당/완료 증거 |
| --- | --- | --- |
| P0 | [ ] 법적 운영 주체·한의원 정식 명칭/책임자·공식 문의처, 제3자/위탁/동일 처리자 관계 확정 | 운영자·한의원 담당자 서면 확인, 필요한 계약 |
| P0 | [ ] 담당자의 수신 권한·업무 이용 동의, 계정 공유/전달/기기 정책 확인 | 계정 접근자·대체 담당·삭제 책임자 지정. 수신 주소 확보/가상 API 성공으로 대체 불가 |
| P0 | [ ] 검사 전 고지/동의 vs 동의 후 서버 확인 방식 선택, 브라우저 저장 동의·민감정보·제공/국외 이전 검토 | 최종 문구와 흐름 승인. 현재 후기 동의만으로 앞선 처리를 덮지 않음 |

| P0 | [ ] 보유기간·삭제/철회·사고 대응·동의 증빙 확정 | 각 사본별 책임자, 기간, 실행·확인 기록, 이용자 요청 대응 연락처 |
| P0 | [ ] 실제 이용자 동의 화면/인증·발신 경로/운영 수신자 분리 개발안 승인 | 현재 mock·가상 입력 전용/테스트 프로젝트 하드코딩을 운영 기능으로 오인 금지. 안전 가드 일괄 제거 금지 |

| P1 | [ ] 브라우저7일 TTL/전체 검진·증명 삭제/공유기기 안내 설계 | 기존 저장 데이터 마이그레이션·이어하기 영향 승인 후 구현·회귀시험 |

| P1 | [ ] 비용/중단/롤백 계획 | 함수당0~1·전체 한도, 공유10건 시험제한과 운영 한도 구분, 월1만원 알림 수신·실제 청구 확인. 알림은 과금 상한 아님 |

## 다음 승인 요청과 이번 작업의 경계

먼저 다음을 결정하면 구현 변경안을 분리하여 제안할 수 있다.

1. 한의원이 앱 운영 주체인가, 독립 앱에서 한의원에 제공하는가? 한의원 정식 명칭·개인정보 담당/공식 문의처·업무 수신 동의 확인 필요.
2. 검사 시작 전 고지/별도 동의를 받아 현재 완료 시각 동작을 유지하는 안을 채택할 것인가? 브라우저7일 TTL/전체 삭제 기능을 함께 개발할 것인가?
3. 발신7일/단순 접수메일 최대30일/임시 다운로드7일 제안과 책임자를 한의원과 검토할 것인가? 진료기록·국외 처리·동의 증거 보관은 법률 검토 후 별도 확정한다.
4. 위 검토 결과를 반영한 Staging 문구·흐름 개발 범위를 승인할 것인가? 이번에는 문서만 작성했으며 승인 전 적용하지 않는다.

앱 코드·수신자·PDF 디자인 변경, 배포, 메일 발송, 실제 환자 처리, 유료 자원 추가, main 병합, 출시 태그 생성은 하지 않았다. 문서 전용 변경으로 npm 테스트/빌드를 재실행하지 않았고 기존 72개 통과 기록과 구분한다. 개인정보 문의처나 법적 보유기간을 임의로 채우지 않았다.
