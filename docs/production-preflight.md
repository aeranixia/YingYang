## 장애 시 롤백 순서 — 실행 계획, 이번 실행 아님

1. 실제 발송을 먼저 차단하고 결과 불명 요청은 재발송하지 않는다. 중복·전역 시도 상태는 유지한다.
2. 증거에 개인정보를 추가하지 않고 배포 직전에 기록한 Hosting release로 되돌린다. 서버/API 계약 변경이 있다면 프런트만 복원하지 말고 호환되는 이전 리비전/설정을 함께 선택한다.
3. 기존 v1.1.1 소스는 위 태그로 복원 가능하나 그 화면은 기존 응답 집계 UI다. v1.2 환자/개인정보 동작이 계속 제공되는 것처럼 표시하지 않는다. 기존 태그는 삭제·덮어쓰지 않는다.
4. 운영 HTTP/자산/설정·발송 차단을 확인하고 배포/복구 결과를 보고한다. 기존 건강정보를 다른 환경으로 복사하지 않는다.

## 현재 판정

Staging 정책 보강·검증 대상은 완료 가능한 범위다. 실제 환자 운영은 **처리경로 확정 회신 부재 + Staging 전용 구성 + 운영 승인 부재**로 아직 배포 직전 완료 상태가 아니다. 단순 Firebase 배포 명령만 실행하면 해결된다고 안내하지 않는다. 운영 전용 구성 준비는 사용자 승인 범위가 확정된 뒤 진행하며 이번에 운영 보안 제한을 변경하지 않는다.
