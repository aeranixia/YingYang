# #7 관리자 페이지·발송 이력·PDF 7일 다운로드

개발 브랜치 develop/v1.2, 적용 대상 yingyangtest. #4는 사용자 지시로 보류하고 운영/main/출시 태그는 변경하지 않는다. 실제 Gmail 발송 창은 닫힌 상태를 유지한다.

## 접근 방법

https://yingyangtest.web.app/admin 에서 기존 Staging 테스트 계정 로그인 → 테스트 접근 권한과 서버 확인. 기존 로그인 세션이면 로그아웃 후 재로그인하여 새 관리자 claim을 반영한다. 검사 화면에서도 관리자 페이지 버튼으로 이동할 수 있다. 비밀번호는 기존 Secret Manager에서 확인하며 이슈/문서에 값은 기록하지 않는다.

서버는 Staging 프로젝트, 테스트 계정 권한, **stagingAdmin 관리자 claim**, Auth 및 App Check를 모두 확인한다. URL이나 버튼을 숨기는 것만으로 권한을 대신하지 않는다. 관리자 이외에는 목록/다운로드 API를 거부한다.

## 구현

- 마스킹 이름(예: 김*동), 전화번호 끝4자리, PDF 생성·처리 시각(KST), 대기/성공/실패, 안전한 오류 코드만 이력에 기록한다. 전체 이름·번호·응답은 로그 JSON에 넣지 않는다.
- 모의 처리 성공은 실제 발송 성공으로 표시하지 않는다. Gmail 성공은 API 접수이며 수신함 도착 확인이 아니다. 결과 불명은 실패/결과 불명 코드로 표시하고 재발송하지 않는다.
- 날짜·상태 필터와 페이지 단위 더보기. 현재 페이지 처리 시각순 정렬이며 저장소 목록 커서로 다음 페이지를 조회한다. 자동 폴링은 하지 않는다. 관리자 호출은 기존 방식의 프로세스당 분당5회 제한으로 보호한다.
- 실패 PDF를 포함한 보관 PDF는 관리자만 다운로드할 수 있다. 관리자 다운로드 이름은 검사결과_끝4자리.pdf로 개인정보 노출을 줄이며 기존 이메일 첨부 이름_끝4자리.pdf와 PDF 내용/양식은 유지한다.
- PDF 생성 후 서버 시각 기준7×24시간, 재시도/상태 갱신으로 연장하지 않는다. 만료 시 다운로드는 즉시 차단하고 해당 객체 삭제를 시도한다. 다운로드 도중 만료해도 반환 전 다시 검사한다.
- 로그인/다운로드 권한은 서버 검증, 응답 no-store, 공개 URL/서명 URL 없음. Blob URL은 다운로드 후 해제하며 브라우저 검사 저장소에 PDF·이력을 저장하지 않는다. 이미 내려받은 파일은 관리자 책임이며 원격 회수할 수 없다.
- 조회/다운로드 접근 기록은 별도 JSON으로 관리자 UID의 HMAC 표식·시각·행위·결과·요청ID만 남긴다. 원본 UID·토큰/IP·이름/전화/PDF를 기록하지 않는다. 접근 기록 저장 실패 때 PDF를 반환하지 않는다. 인증이 없는 프레임워크 차단 요청은 플랫폼 보안 로그와 구분한다.
- 배포 이후 처리 건부터 기록한다. 과거 메일을 읽거나 없는 과거 PDF를 복원/추정하지 않는다. gmail.send 권한은 변경하지 않았다.

## 저장소·권한·보관

전용 GCS yingyangtest-admin-reports-495270334718, STANDARD/서울. Public Access Prevention enforced, Uniform Bucket Access, versioning off, soft delete0. PDF/logs/access 객체에 생성7일 Delete lifecycle. 기존 메일 중복 표식 버킷의2일 정책은 변경하지 않는다.

실행 서비스 계정은 기존 계정이며 새 비밀키/서비스 계정은 만들지 않는다. 해당 버킷에만 storage.objectAdmin을 추가하여 읽기·목록·조건부쓰기·만료 삭제를 허용한다. 일반 브라우저에는 GCS IAM 권한을 부여하지 않는다. 기존 테스트 계정에 stagingAdmin claim을 추가하고 기존 claim을 보존했다.

[Google 공식 수명주기 설명](https://docs.cloud.google.com/storage/docs/lifecycle)에 따라 자동 삭제는 비동기적이다. **7일 정각 물리 삭제를 보장하지 않는다.** 서버는 객체가 남아 있어도 만료 즉시 조회/다운로드를 차단한다. 접근 기록은 각 행위 생성 후7일 삭제 정책이며 이력 객체 상태 갱신과 무관하게 PDF의 논리 만료는 최초 생성 기준이다.

[공식 요금](https://cloud.google.com/storage/pricing)은 저장량·연산·네트워크 기준 종량제다. STANDARD로 최소 보관일 과금이 있는 저빈도 클래스를 피했다. 예시 하루50개·PDF1MiB·7일이면 약350MiB PDF 보관량이며 이는 사용량 가정이지 강제 과금 상한이 아니다. 준비 실패·모의 처리·메타데이터/조회·다운로드·빌드/Functions 비용은 별도다. 새 고정비 서비스·DB·Redis·스케줄러는 추가하지 않았다.

## 실패·중복 보존

PDF 보관 실패는 발송 전에 실패 처리한다. 실제 Gmail이 접수된 뒤 이력 상태 갱신만 실패한 경우, 기존 공유 발송 성공/불명 표식을 유지하며 자동 재발송하지 않는다. 이력에는 대기가 남을 수 있어 UI에서 대기를 ‘진행 중 또는 최종 상태 미확인’으로 설명한다. 관리자 다운로드는 상태에 관계없이 권한·보관기간을 확인하므로 파일을 확인할 수 있다. 이력과 Gmail 전달을 하나의 원자적 트랜잭션으로 보장하지 않는다.

공유 메일 중복 방지·KST50회 시도 제한·결과 불명 자동 재시도 금지는 유지한다. 모의 처리의 기존 프로세스 메모리 중복 제한을 영구 전역 보장으로 바꾸었다고 주장하지 않는다.

## 안내·개발 경계

PDF에 전체 이름·번호·집계가 들어 있는7일 비공개 보관 사실과 관리자 접근 기록을 정책·검사 전/후 안내에 추가했다. 변경된 범위에 재동의를 받도록 버전을 갱신했으며 기존 응답·저장일/키는 유지한다. #4의 운영 법적 검토를 완료하거나 운영 배포를 재개하는 변경은 아니다. 가상 정보만 사용한다.

롤백은 개발 브랜치의 직전 커밋3a093ad와 기록된 이전 Hosting/Functions 리비전을 기준으로 한다. 기능 플래그 STAGING_ADMIN_ARCHIVE_ENABLED를 끄면 새 PDF 보관/관리자 API를 차단할 수 있지만 기존 비공개 보관분은 만료 정책으로 정리해야 한다. 이미 내려받은 사본은 회수되지 않는다. 새 버킷을 보존 정책 확인 없이 삭제하거나 운영에 복사하지 않는다.
