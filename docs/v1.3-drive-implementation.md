# v1.3 Drive 백업 구현 기록

이슈 #8 댓글6554860407을 반영한다. develop/v1.3에서만 개발하며 운영/main/출시 태그는 변경하지 않는다.

## 구현

- PDF 표시 제목과 문서 제목은 `체질검사 결과`.
- 신규 PDF의 이메일·관리자 다운로드·Drive 파일명은 `YYMMDD_실명이름_끝4자리.pdf`. KST 완료 확인 날짜를 쓰고 이전 완료 증명이 없으면 최초 생성 날짜를 고정한다. 알려진 실패 재시도가 자정을 넘어도 날짜는 유지한다.
- 신규 PDF 파일명은 비공개 PDF 객체 메타데이터에만 함께 저장한다. 목록/일반 로그는 기존 마스킹을 유지한다. v1.2에 생성돼 파일명 메타데이터가 없는 기존 PDF의 실명을 추정하지 않으며 호환용 이름으로 다운로드한다. 과거 PDF를 일괄 재작성하지 않는다.
- 기존 관리자 PDF 원본·목록·감사 기록의 7일 보관/만료는 유지한다.
- Staging PDF 객체 생성 이벤트가 별도 백업 함수를 실행한다. 이메일 요청은 Drive 완료를 기다리지 않으며 백업 함수에서 이메일을 발송하지 않는다.
- 백업 기본 OFF, 모의/Google 모드 구분. 모의 모드는 실제 Drive 파일을 만들지 않는다. 실제 모드는 별도 Drive Secret·고정 계정/폴더 확인 후에만 활성화 가능하다.
- 계정 ukclinic.official@gmail.com, 폴더 YingYang_검진결과_백업. 발신 hoyunum1130@gmail.com 유지.
- Drive 삭제 API·삭제 UI·자동 파기 스케줄러 없음. 삭제는 계정 소유자가 Drive에서 직접 관리한다. 일반 관리자에게 백업 설정/상태 API를 허용하지 않는다.
- 마스터 최근 Google 본인 확인 후 설정 저장/재시도, Auth/App Check 및 Staging 프로젝트 제한 적용.
- GCS 세대 조건 예약, 업로드 전 파일ID 영속 기록, 같은 ID 재시도와 원격 MD5/크기/폴더/파일명 대조로 중복 방지. 재시도 최대5회, 지수 지연, 원본7일 기한 제한. 성공 기록은 원본 만료 후에도 유지한다.
- 백업 상태에는 파일ID·해시·시간·상태만 저장하고 이름·전체 번호·원 응답·PDF 본문을 기록하지 않는다. 원본 파일명은 Drive 실제 파일과 기존 비공개 PDF 메타데이터에 포함된다.
- Staging 기존 공유 저장소의 수명 정책을 메일 집계/작업 prefix만2일로 제한해 백업 기록/설정은 자동 만료되지 않도록 한다. Drive 파일을 지우는 수명 정책이 아니다.

## 검증과 제한

- UI74 + 배포 보호5 + 서버/PDF/백업73 = 152개 통과. npm test, npm run build, build:staging, functions:build, functions:test 성공.
- Chrome/WebKit 모의 인증으로 guest/master/admin 권한별 탭 분리와320/390/768/820/1024/1440px 검수. WebKit fieldset 레이아웃 넘침을 수정하고 다시 확인했다. 실제 개인 Google 로그인·실제 기기 검증은 아니다.
- 가상 PDF를 pdfjs/canvas로 실제 렌더링해 제목·한글·숫자·표·A4한페이지를 확인했다. docs/previews/issue-8-pdf.png 및 issue-8-admin.png는 가상 자료/모의 화면이다.

기존 테스트와 추가 Drive 모의 테스트, UI/빌드 결과 및 Staging 실제 배포 검증은 이슈 #8에 보고한다. 실제 Gmail 시험 발송과 실제 환자 자료 전송은 하지 않는다.

Drive 실제 연결에는 계정 소유자의 별도 OAuth 동의와 Staging 전용 `STAGING_DRIVE_CONFIG` 설정이 필요하다. 값은 서버 Secret에만 보관한다. 인증정보가 없을 때 Google 모드 활성화는 실패하며 모의 성공을 실제 Drive 업로드 성공으로 표시하지 않는다.

운영 Drive 연결/배포는 Staging 실제 가상 업로드 검증 및 사용자 별도 승인 후 진행한다. 현재 백업 이벤트/관리 API는 Staging에만 연결돼 있다. 운영은 v1.2.0 유지한다.
