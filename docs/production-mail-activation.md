# 운영 이메일 전송 활성화

2026-11-01 사용자 전송 활성화 지시 및 운영 Gmail 소유자의 OAuth 동의를 기준으로 진행한다. 과거 발송 중지 보고는 이 변경 전 상태다.

## 구현과 제어

- 운영 프로젝트 yingyangcheck 전용 클라이언트·Secret을 사용한다. Staging 인증값을 복사하지 않는다.
- Gmail 전송 권한과 발신 계정의 서명된 Google ID를 확인했다. 토큰 갱신을 확인했으며 시험 메일은 발송하지 않았다.
- 브라우저는 수신자·발신자를 지정할 수 없다. 기존 Gmail 발신자와 한의원 고정 수신자를 서버 Secret에서 확인했다.
- 환경 플래그, Secret enabled, 기존 상태 저장소 v1/control/mail의 enabled가 모두 참이어야 전송한다. 설정 오류·만료 시 차단한다.
- 두 검사 완료 및 사전 동의 증명을 확인한 뒤 이름·전화번호·별도 PDF 동의를 검증한다. 서버에서 기존 규칙으로 재집계한다.
- 이름·전화번호 입력값과 발송 티켓은 브라우저 영구 저장 대상이 아니다. 검사 응답·동의·완료 증명은 기존 7일 규칙을 따른다.
- PDF 좌표·폰트·집계표·첨부 파일명 규칙은 유지하고 운영 환경 표시만 사용한다. 관리자 다운로드의 마스킹 이름과 PDF 7일 접근 제한은 유지한다.

## 중복·실패·보관

- 동일 익명 세션의 동일 완료 증명·응답은 재접속 또는 새 티켓에도 같은 작업 식별자를 사용한다. 수정된 개인정보로 같은 작업을 덮어쓰지 않는다.
- 알려진 발송 전 실패는 같은 작업으로 최대 3회 재시도한다. Gmail 요청 이후 결과 불명·타임아웃은 재발송하지 않고 관리자 확인이 필요하다.
- Gmail 접수 성공은 수신함 도착 확인이 아니다. 앱은 둘을 구분해 안내한다.
- KST 날짜별 전역 50회는 성공 건수가 아닌 시도 예약 횟수다. 기존 GCS 세대 조건으로 동시 초과를 막으며 예약 후 실패를 환급하지 않는다.
- 기존 상태 저장소의 일일 횟수는 생성 후 2일, 중복 표식은 7일 완료 증명의 유효기간보다 긴 8일 삭제 대상으로 둔다. 제어 설정은 수명 정책에서 제외한다. 새 저장소·DB·서비스 계정은 만들지 않는다.
- 공유 표식에는 이름·전화번호·원 응답·PDF를 기록하지 않는다. PDF는 기존 승인된 비공개 관리자 저장소에 최대 7일 접근 가능하다. 저장소 물리 삭제는 비동기적이다.
- Gmail·수신 메일함의 보관·삭제 책임은 기존 방침을 따른다. 토큰은 만료·철회될 수 있으며 오류 발생 시 재인증이 필요하다. 이번 응답에 갱신 토큰의 만료 기간은 제공되지 않았다.

## 검증 상태

- UI 71개, 배포 보호 5개, 서버 62개: 총 138개 통과.
- 운영·Staging·Functions 빌드 성공. 운영 전용 프로젝트·SDK·빌드 보호 검증 적용.
- 실제 이메일 요청은 실행하지 않는다. 서버 메일 경로는 모의 발신기로 검증하며 배포 후 UI 전송 점검도 실제 발송 요청을 차단한다.
- 운영 배포 및 실제 브라우저 결과는 완료 후 기록한다. 실제 기기와 한의원 수신함 도착은 이번 검증 범위에 포함하지 않는다.

## 중지·롤백

긴급 중지는 공유 제어 v1/control/mail을 enabled:false로 변경한다. 이후 환경 플래그와 Secret도 닫아 배포한다. 개인정보 노출·수신자 오설정·검사 진행 실패·권한 우회·중복 발송이 확인되면 먼저 발송을 중지하고 검증된 이전 Hosting/Functions 커밋으로 롤백한다. 기존 PDF·승인 계정 자료는 임의 삭제하지 않는다.
