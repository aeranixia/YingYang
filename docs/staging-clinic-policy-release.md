## 클라우드 읽기 전용 재진단

Google Cloud API로 Firebase App Check 등록, reCAPTCHA Enterprise 설정/집계, Cloud Logging 검증·감사 정보를 조회했다. Cloud Console UI 직접 조작이 아닌 동일 서비스 API 조회다.

- App Check 등록 있음, TTL3600초, minValidScore0.5. 점수형 키, 테스트 도메인2개, 전체 도메인 허용 아님, 테스트 점수 설정 없음.
- 집계는 이전과 동일: 2026-08-02 시작90일, index85의0.9=33건/1.0=2건. 자동화 실패 요청의 개별 점수·invalid reason·브라우저 연계 정보는 확보하지 못했다.
- 검증 로그22건: Auth/App VALID19건, Auth VALID/App MISSING3건. 이번 Chrome 실패와 직접 연결되는 증거는 없다.
- 오류 감사 조회는 초기 필드 선택 요청400 후 타임스탬프만 선택한 조회로 성공: 일치0건. 오류 기록 부재는 오류 해소 증거가 아니다.
- 새 브라우저 실패 재현·평가 생성·보안 설정 변경 없음. 재진단은 최신 승인에 따른 기존 정보 읽기만 수행.

원인 미확정. 자동화 환경 특유 현상 가능성과 일반 사용자 정상 보고는 구분하되 자동화 전용이라고 확정하지 않는다. 일반 사용자 영향 범위도 정량 확정 불가. 보안 완화/우회는 제안하거나 적용하지 않는다. 변경 근거가 부족하므로 이번 App Check 수정 없음. 운영 배포 판단은 사용자 최종 승인 대기다.

## 남은 확인 및 승인

정식 상호/법적 주체, 보호책임자 지정·연락 정보, 외부 지원 계약/위탁, 공급자 국외 처리 정보·근거, 동의 증빙 및 로그·메일·의료기록 보관·삭제 기준은 추정하지 않았다. Staging에 미확인으로 표시하며 최종 운영 게시 전 확인 필요다.

변경된 Staging 정책/검사 전 안내 화면의 사용자 검수와 이후 운영 배포 최종 승인은 별개다. 기존 기능 전체 수동 재검증이나 PDF/메일 재수신을 요구하지 않는다. 운영 프로젝트·main·출시 태그는 변경하지 않고 이슈 #4는 열린 상태로 유지한다.

배포 확인: yingyangtest Hosting/Functions 배포 성공. 배포 주소와 JS HTTP200, 내려받은 JS SHA-256이 로컬 Staging 빌드와 일치. noindex/nofollow/noarchive 및 no-store 유지. 운영 HTML HTTP200 및 기존 기준 해시 일치. 배포 후 일반 사용자 인증/화면 조작은 수행하지 않았으며 변경 화면 사용자 검수 대기.
